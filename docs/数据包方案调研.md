# HeartStealer(夺心者)功能 —— 数据包方案调研报告

> 结论先行:**数据包只能实现"核心玩法的一部分"(开局半颗心 + 杀怪变强 + 死亡保留 + 近战变强),而且要做不少妥协;三个关键功能(突破 1024 上限、远程/投掷物伤害加成、HUD 显示)是数据包做不了的,必须靠 Mod。**
> 调研日期:2026-08-13 | 依据:Minecraft 官方 wiki(Attribute / Data pack)+ 本模组已字节码验证的游戏机制。

---

## 一、先说结论(30 秒版)

| 你的需求 | 数据包能做吗 | 一句话原因 |
|---------|-------------|-----------|
| 开局半颗心 | ✅ 能 | 命令改玩家 `max_health` 属性 |
| 击杀生命上限加成 | ⚠️ 打折能做 | 只能"按生物类型查表"写死加成,拿不到被杀个体实际生命 |
| 击杀回复血量 | ✅ 能 | `instant_health` 瞬间治疗 |
| 近战攻击力加成 | ✅ 能 | 命令加 `attack_damage` 属性修饰符 |
| **远程/投掷物伤害加成** | ❌ **不能** | 伤害结算是 Java 代码,数据包够不着 |
| **突破 1024 生命上限** | ❌ **不能** | 上限钳制是 Java 硬编码,数据包无法修改 |
| **HUD 显示"攻击+N / 生命 N"** | ❌ **不能** | 屏幕渲染是客户端/资源包的事,数据包管不了 |
| 死亡无惩罚 | ✅ 能 | 属性自动存档,天然保留 |
| 击杀范围/黑名单/PvP 开关 | ⚠️ 部分能 | 按实体类型可做;按对方实际生命做不到 |
| 配置界面 | ❌ 不能 | 数据包没有图形界面 |

## 二、数据包到底能干什么(机制背景)

数据包(Data Pack)是放在世界/服务器里的**服务端内容包**,主要包含:
- **函数(function)**:用命令写脚本,可挂在 `tick`(每 tick 执行)、`load`(加载时执行)上;
- **进度(advancement)**:除了成就,还能当**"事件监听器"**用 —— 比如 `minecraft:player_killed_entity` 触发器可以监听"玩家击杀了实体",然后奖励执行一个函数;
- **标签 / 谓词 / 战利品表 / 配方 / 伤害类型** 等。

**关键限制(官方 wiki 明确)**:
1. 数据包管的是**服务端的世界内容**;**客户端表现(血条、HUD、贴图、渲染)属于"资源包"系统**,数据包够不着;
2. 数据包**不能修改游戏引擎的 Java 硬编码逻辑**(比如属性的上下限),只能调用命令去操作游戏已经开放的接口;
3. 属性的最终值**一律被钳制在属性的最小/最大范围内**(官方 wiki 原文:The final value is clamped to fit the attribute's minimum and maximum value range)。

## 三、能做的部分:怎么实现(技术骨架)

### 1. 开局半颗心
一个 `tick` 函数,检测"还没有被初始化过"的玩家(用一个计分板标记),然后:
```
execute as @a unless score @s hs_init matches 1 run attribute @s minecraft:max_health base set 1.0
scoreboard players set @a[scores={hs_init=0}] hs_init 1
```

### 2. 击杀生命上限加成 + 回血 + 攻击力加成
用**进度(player_killed_entity)** 做监听,每个生物类型一个触发器(或按标签分组),奖励函数执行:
```
# 读当前生命上限到计分板
execute store result score #hp hs attribute @s minecraft:max_health base get
# 加上"该类型生物的加成"(写死,如僵尸 +20、鸡 +4)
scoreboard players add #hp hs 20
# 把新值写回属性
execute store result attribute @s minecraft:max_health base set 1.0 run scoreboard players get #hp hs
# 回血
effect give @s minecraft:instant_health 1 0 true
# 近战攻击力加成
attribute @s minecraft:attack_damage modifier add <固定UUID> <名字> 1 add_value
```

### 3. 死亡保留
什么都不用做 —— 属性值本来就被原版写进玩家存档,重生/重登自动保留。

## 四、做不了的部分:为什么(原理)

### ❌ 突破 1024 生命上限
原版 `max_health` 属性在 **Java 代码里**被定义成范围 **1.0 ~ 1024.0(512 颗心)**。任何途径(命令 `set`、属性修饰符)设置的值,在**读取生效时都会被钳制回这个范围**。
- 数据包只能"调属性值",**改不了属性本身的取值范围**(那是 Java 类 `RangedAttribute` 写死的)。
- 本模组之所以能突破,是因为用 **Mixin 拦截了钳制方法** `Attribute.sanitizeValue()`(我们当时字节码验证过:钳制发生在读取路径 `getValue()→sanitizeValue()`)。**这种"改 Java 代码"的能力,数据包不具备。**
- 佐证:官方 wiki 明确"最终值被钳制在属性的最小/最大范围内"。

### ❌ 远程 / 投掷物伤害加成
- 近战伤害吃玩家的 `attack_damage` 属性 → 数据包能加。
- **远程(弓/弩/三叉戟投掷)、投掷物(雪球/鸡蛋/药水)伤害不吃 `attack_damage`**,1.21.11 也**没有**"弹射物伤害"属性(我们已确认 `Attributes` 类里不存在 `PROJECTILE_DAMAGE`)。
- 要给它们加伤害,必须在**伤害结算事件**里手动改伤害值(本模组的 `LivingEntityHurtMixin` 就是这么做的)。数据包没有"伤害事件"这个接口,函数/命令**碰不到伤害计算**。

### ❌ HUD 显示"攻击 +N / 生命 N"
- 屏幕上的血条、文字是**客户端渲染**。数据包是服务端内容,管不了客户端怎么画。
- 资源包只能**换贴图**,不能动态画"攻击 +N"这种文字 HUD(那需要代码)。
- 退而求其次只能用 `title ... actionbar` 临时显示几秒,无法常驻、无法做成自定义血条。原版红心也没法被数据包隐藏。

### ⚠️ 击杀加成只能"查表"不能"动态读属性"
- 数据包监听 `player_killed_entity` 时,能拿到击杀者,但**拿不到"刚被杀的那一只"的实际属性值**(实体已被移除,而且无法精确定位是哪一只)。
- 所以"生命上限 += 该生物最大生命"只能退化成:每种生物**写死**一个加成值(僵尸 +20、鸡 +4……)。
- 对原版普通生物来说,最大生命本来就是固定值,查表结果基本一致;**但遇到被强化/附魔/别的 Mod 改过的生物就会不准**;PvP"按对方当前生命加成"也做不到。

## 五、数据包 vs Mod 方案对比

| 维度 | 数据包方案 | Mod 方案(本模组) |
|------|-----------|-----------------|
| 是否要装 Mod | 不用,纯原版(单机/服务器放数据包即可) | 主机/服务器要装 Fabric 模组 |
| 开局半颗心 | ✅ | ✅ |
| 杀怪加生命(查表) | ⚠️ 打折 | ✅ 动态读实际生命 |
| 杀怪回血 | ✅ | ✅ |
| 近战攻击加成 | ✅ | ✅ |
| 远程/投掷物加成 | ❌ | ✅ |
| 突破 1024 上限 | ❌ | ✅(maxHealthCap 配置) |
| HUD 显示攻击/生命 | ❌ | ✅ |
| 配置界面 | ❌(改 json/初始化函数) | ✅(Cloth Config 图形界面) |
| 联机 | 服务端生效,客户端无自定义界面 | 客户端装模组可看自定义界面 |
| 制作难度 | 中(要写一堆 advancement + 函数) | 已做好 |

## 六、给你的建议

1. **如果你想要"不装任何 Mod 也能玩"的轻量版** → 可以做一份**精简数据包**:开局半颗心 + 杀怪按类型查表加生命/回血 + 近战攻击加成 + 死亡保留。这是数据包能做到的完整子集,适合分享给"纯净原版"玩家。
2. **如果你要完整体验(突破 1024、远程/投掷物加成、HUD、配置界面)** → 必须用 Mod,也就是现在的 HeartStealer。
3. **可以两者都提供**:数据包当"轻量体验版",Mod 当"完整版"——互不冲突。

> 一句话总结:**数据包是把"玩法逻辑"搭在命令上,Mod 是把"玩法逻辑"搭在 Java 代码上;你的需求里有三处(1024 上限、远程伤害、HUD)必须碰 Java,所以只能靠 Mod。**
