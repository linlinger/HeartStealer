# HeartStealer(夺心者)代码阅读指南

> 写给不会写代码的你:这份指南告诉你**从哪开始看、按什么顺序看、每个文件是干嘛的**。跟着走一遍,你就能读懂这个模组是怎么"转"起来的。

---

## 〇、先搞懂三件事

1. **模组是什么**:一个"开局半颗心、杀怪变强"的 Minecraft 模组。
2. **代码分两半**:
   - `src/main/` —— **服务端/共用逻辑**(游戏规则:血量、攻击力、击杀奖励、存档)。这是核心。
   - `src/client/` —— **客户端显示**(屏幕上画给你的:血条、攻击力数字)。只是"给你看"。
3. **看懂代码不需要会写代码**:每个文件都有中文注释,你只需要顺着"一条主线"走,遇到不懂的方块按图索骥。

## 一、从哪开始看?(10 分钟路线图)

| 顺序 | 看什么 | 为什么 |
|------|--------|--------|
| ① | `src/main/java/linlinger/heartstealer/Heartstealer.java` | **模组大门**:游戏启动时第一个执行的文件,所有"接线"都在这 |
| ② | `config/HeartStealerConfig.java` | 认识"配置项":开局血量、每杀+几攻击、血条模式等,全部能改 |
| ③ | `attribute/PlayerAttributeManager.java` | **心脏**:血量怎么改、攻击力怎么加、怎么存档 |
| ④ | `handler/KillEventHandler.java` | **触发器**:怎么判断"这是玩家杀死的",怎么发奖励 |
| ⑤ | `handler/PlayerRespawnHandler.java` | 死亡重生怎么"不掉属性" |
| ⑥ | `client/.../HeartstealerClient.java` + `client/.../hud/HeartStealerHud.java` | **给你看的**:屏幕角落的血条/攻击力数字怎么画的 |

看完 ① ~ ⑤,你就懂了 90% 的玩法逻辑;⑥ 是锦上添花的显示。

## 二、主线剧情:一次"击杀"是怎么发生的

用大白话讲一遍,配合代码注释看:

```
玩家挥剑砍死一只兔子
        │
        ▼
① 游戏自己通知:兔子死了,谁杀的?(DamageSource)
        │
        ▼
② KillEventHandler 收到通知(ServerLivingEntityEvents.AFTER_DEATH)
   - 判断:是玩家杀的吗?(直接挥剑 / 射箭 / 扔三叉戟)
   - 判断:这个生物该不该算?(黑名单?Boss?被动?)
        │
        ▼
③ 算奖励:兔子最大生命 10 → 生命 +10;攻击力 +1
        │
        ▼
④ PlayerAttributeManager 执行修改
   - 生命上限:把"生命上限"这个属性 base 值 +10
   - 攻击力:在"攻击力"属性上加一个"固定编号的加成"(+1)
        │
        ▼
⑤ 屏幕上:HUD 刷新,显示 生命 520 / 攻击 +15
```

## 三、每个文件逐个说(读完即通关)

### 1. `Heartstealer.java` —— 模组大门(必读)
- `onInitialize()`:游戏启动时跑一次。它只做三件事:
  1. 读配置(`AutoConfig` 帮你从 `config/heartstealer.json` 读进来);
  2. 挂上"玩家进服"监听 → 把新玩家血条改成半颗心;
  3. 挂上"实体死亡"监听 → 交给 `KillEventHandler` 处理;
  4. 挂上"重生复制"监听 → 死亡不掉属性。
- `id(...)`:一个造名字的小工具,模组里所有资源/编号都用它。

### 2. `config/HeartStealerConfig.java` —— 设置面板(读字段名即可)
- 每个 `public 类型 名字 = 默认值;` 就是一项配置。
- 想改默认值?直接改这里的数字,或让玩家在 ModMenu 界面改,效果一样。
- 玩家改完存进 `config/heartstealer.json`。

### 3. `attribute/PlayerAttributeManager.java` —— 数值管家(核心中的核心)
- `ATTACK_DAMAGE_MODIFIER_ID`:攻击力加成的"固定编号"。因为武器也会影响攻击力,我们用一个"加了编号的加成"来区分,这样**不会和武器伤害算重复**。
- `initPlayerHealth()`:开局改血。判断"还是原版默认 20 血?"→ 是,说明新玩家,改成半颗心。
- `addKillReward()`:加血 + 加攻击。
- `getAttackBonus()`:读取当前攻击力加成(给 HUD 显示用)。
- 为什么生命用 `setBaseValue`、攻击用 `modifier`?因为生命 base 会被游戏自动存档,攻击力 base 会和武器混在一起,用 modifier 更干净。

### 4. `handler/KillEventHandler.java` —— 裁判(判断"算不算")
- 三连问:是玩家杀的吗 → 这个怪算吗 → 给多少。
- "玩家杀的"判定:看伤害来源 `DamageSource` —— 直接攻击者,或弹射物(箭)的主人。
- 黑名单、Boss 倍率、各种开关都在这里拦。

### 5. `handler/PlayerRespawnHandler.java` —— 保险柜
- 死亡后,游戏会造一个新的玩家替身。它把旧玩家的血量和攻击加成"复制"到新替身上 → 看起来就像"没死过"。
- `keepOnDeath` 开关决定要不要复制(默认要)。

### 6. `client/.../HeartstealerClient.java` —— 客户端入口
- 客户端专属:把"画屏幕"的任务注册给游戏(`HudRenderCallback`)。

### 7. `client/.../hud/HeartStealerHud.java` —— 画屏幕给你看
- 读玩家当前的攻击加成和最大生命,画一个半透明小面板。
- DNF 模式:画一排彩色小方块,一个方块代表"一管"(60 点血),超过配置层数就显示 `超出 +N`。
- NUMERIC 模式:不画彩块,超过 3 排就显示 `超出 +N`。
- 面板位置由 `hudPosition` 决定(四角)。

## 四、这些"黑话"是什么意思

| 黑话 | 意思 |
|------|------|
| Attribute / 属性 | 游戏里可量化的数值,如"最大生命""攻击力" |
| Base value / 基础值 | 属性的"出厂值",会被存档 |
| Modifier / 修饰符 | 在基础值之上临时/永久叠加的加成,带编号、可移除 |
| Event / 事件 | 游戏里发生的事(玩家进服、实体死亡),我们可以"订阅"后插一脚 |
| Mixin | 一种"偷偷改游戏原代码"的技术。本模组在几处用到:突破生命上限(`AttributeCapMixin`)、远程伤害加成(`LivingEntityHurtMixin`)、隐藏原版红心/装甲栏(`GuiHeartsMixin`/`GuiArmorMixin`) |
| Mojang Mappings | 游戏源代码的官方命名(我们代码里的类名来源) |
| HUD | 屏幕上的信息界面(血条、物品栏那一片) |

## 五、常见疑问

- **为什么血条不直接改原版,而是自己画一层?**
  答:直接改原版血条渲染需要"反编译源码"确认内部方法(很复杂且容易崩)。我们自己画一层彩色指示 + 数字,稳定、安全,效果直观。

- **杀掉 Boss 血条会不会铺满屏?**
  答:不会。面板只显示 5 个彩块(可配置),超出部分用 `+N` 数字表达。

- **攻击力为什么不用"每次 +1 直接写死"?**
  答:因为要让你在配置文件里改"每次加多少",所以存的是"加成值"而不是写死的代码。

- **想自己改数值?**
  答:进游戏 → Mods → HeartStealer → 配置,全部可视化改,不用碰代码。

## 七、1.21.11 特别说明(看代码时遇到这些名字别慌)

Minecraft 1.21.11 换用新的官方映射,几个类被**改名**了,网上老教程的名字在这里是错的:

- 老教程的 `ResourceLocation` → 现在叫 **`Identifier`**(`net.minecraft.resources.Identifier`)
- 老教程的 `MobType` / `getMobType()` → 被移除,判断敌对生物改用
  `entity.getType().getCategory() == MobCategory.MONSTER`
- 老教程的 `RenderTickCounter` → 现在叫 **`DeltaTracker`**(`net.minecraft.client.DeltaTracker`)

看到代码里出现 `Identifier`、`MobCategory`、`DeltaTracker`,就是对应这些老名字。

## 八、HUD 说明(2026-08-13 双模式渲染)

- **两种渲染模式,运行时自动切换**(核心在 `client/hud/HeartStealerHud.java` 的 `shouldUseCustomRender()`):
  1. **纯文字模式**:装了 colorfulhearts(可选依赖,负责血条渲染)或配置 `customHealthBar=false` → 本模组**不隐藏原版红心/装甲栏**,只在原版装甲栏上方画两行文字 `攻击 +N`、`生命 N`。
  2. **自定义模式**:没装 colorfulhearts 且配置开启 → `GuiHeartsMixin`/`GuiArmorMixin` 条件化隐藏原版红心与装甲栏,自绘 60×8px 红条(位置同原版红心第一排:中线往左 91、距底部 39;`当前/最大` 内嵌居中;中毒/凋零/冰冻变色)+ 原版样式装甲栏 + 两行文字。
- **检测方式**:`FabricLoader.isModLoaded("colorfulhearts")`,可靠无副作用;`fabric.mod.json` 的 `suggests` 里把 colorfulhearts 声明为**可选依赖**。
- **两个 Mixin 是"按需"的**:只有自定义渲染开启时才 `ci.cancel()`,否则放行原版,所以不会和 colorfulhearts 抢着渲染同一块画面。
- **攻击数字怎么来的**:服务端击杀后 `PlayerAttributeManager.syncAttackToClient()` 主动发原版"更新属性"包给客户端(在进服 / 击杀 / 重生三处都会调用),所以 HUD 能实时显示真实加成。
- **ModMenu 配置入口**:在 `fabric.mod.json` 里声明了 `"modmenu"` 入口点指向 `ModMenuIntegration`,ModMenu 里才有 ⚙️ 配置图标。
- 旧的 DNF 彩色方块/数字补偿模式已简化掉,`healthBarMode`/`layerColors` 等配置项暂不生效(后续可清理);新增 `customHealthBar` 配置项控制本模组自绘开关。

## 九、伤害加成说明(2026-08-13:近战/远程/投掷物全覆盖)

**加成作用范围**(读 `src/main/java/linlinger/heartstealer/mixin/LivingEntityHurtMixin.java`):

| 伤害类型 | 谁加的伤害 | 怎么判定 | 是否加成 |
|---------|-----------|---------|---------|
| 近战(剑/斧/徒手/横扫) | 玩家本人 | `source.getDirectEntity()` 是玩家 | ✅ 已有(`ATTACK_DAMAGE` 属性修饰符,不走本 mixin) |
| 远程(弓/弩/三叉戟投掷) | 弹射物,主人是玩家 | 直接实体是 `Projectile` 且 `getOwner()` 是玩家 | ✅ 本 mixin 加 |
| 投掷物(雪球/鸡蛋/喷溅药水) | 弹射物,主人是玩家 | 同上 | ✅ 本 mixin 加 |
| TNT 爆炸(你点燃) | 点燃的 TNT 实体 | 直接实体是 TNT,**不是 Projectile** | ❌ 天然排除 |
| 重生锚 / 末地床爆炸 | 无直接实体 | 直接实体是空 | ❌ 天然排除 |
| 苦力怕等生物爆炸 | 生物本体 | 直接实体不是玩家弹射物 | ❌ 天然排除 |

- **为什么近战不在这里加?** 近战已经通过 `ATTACK_DAMAGE` 属性修饰符加过一次,如果这里再加会**双倍**。所以本 mixin 只认"弹射物 + 主人是玩家"。
- **三种爆炸为什么天然排除、不用写特殊代码?** 因为判定条件写死了"是玩家拥有的弹射物",而 TNT/床/重生锚爆炸的来源实体根本不是弹射物、也没有玩家主人。
- **加成数值从哪来?** `PlayerAttributeManager.getAttackBonus(玩家)`,和近战、HUD 显示的是**同一个"攻击加成点数"**,三者永远一致。
- **注入点技巧**:用 `@Redirect` 重定向 `hurtServer` 内部对 `actuallyHurt` 的调用,把加成加到传给它的伤害值上(护甲/魔抗减免在 `actuallyHurt` 内部,加成吃护甲,和近战一致)。`hurtServer` 里 `actuallyHurt` 被调两次(if/else 互斥分支:无敌帧内只算超出部分 / 正常结算),两个调用点都重定向,但运行时只执行一个,加成只加一次。
- **1.21.11 的坑**:`hurtServer` 比旧版多了 `ServerLevel` 参数;`Projectile` 类在 `net.minecraft.world.entity.projectile` 包里(不是 `world.entity`)。
- **PvP 开关(`pvpDamageBonus`,默认 false)**:本 mixin 里,被打目标是玩家时先查这个配置——关闭(默认)就跳过加成,打玩家保持原版伤害;打怪始终加。
- **攻击力无上限**:原版 `ATTACK_DAMAGE` 属性上限 2048,已由 `AttributeCapMixin` 放开(和生命上限同机制),否则近战加成超 2048 会被原版钳死、与远程不一致。
