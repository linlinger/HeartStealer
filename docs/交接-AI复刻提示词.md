# HeartStealer(夺心者)· AI 复刻交接包

> **用途**:把「HeartStealer」模组完整交接给**另一个 AI 助理**,让它用指定的 Mod Loader / 平台(Forge、NeoForge、Fabric 新版本、Bukkit/Spigot 插件、数据包…)重新实现一份行为一致的版本。
> **使用方法**:① 把下方「§1 一键提示词」整段复制给那个 AI;② 同时把「§2 文档清单」列出的文件路径发给它(或告诉它到项目目录里读);③ 确认「§6 目标平台」填好了再发。
> **版本**:v1.0 | 2026-08-13 | 原版实现:Fabric 1.21.11(本仓库 `heartstealer-template-1.21.11/`)

---

## 1. 一键提示词(整段复制给另一个 AI)

```
【任务】
请用 <目标 Loader / 平台: 例如 Forge 1.21.11 / NeoForge 1.21 / Bukkit 插件 / 数据包> 完整复刻 Minecraft 模组
「HeartStealer(夺心者)」,目标是玩法行为、数值逻辑、可配置性与原版(Fabric 1.21.11 实现)完全一致。

【先读文档(按顺序)】
1. docs/开发需求文档.md —— 全量需求、配置项、技术方案、1.21.11 映射坑、最终交付状态
2. docs/Spec-伤害加成复刻规格.md —— 伤害加成模块的精确规格(判定逻辑、PvP 开关、攻击力上限、验收清单)
3. docs/代码阅读指南.md —— 原版实现的代码结构与每个文件的职责
4. README.md —— 玩法说明、配置表、已知限制

【功能需求全量清单(全部要实现)】
1. 开局半颗心:玩家首次进服,最大生命设为 initialHealth(默认 1.0)。
2. 击杀奖励-生命:击杀任意生物,生命上限 += 该生物当前最大生命;并且当前血量同步回复等量。
3. 击杀奖励-攻击:每次击杀,攻击加成 += attackDamagePerKill(默认 1.0)。
4. 伤害加成覆盖所有武器:近战、远程(弓/弩/三叉戟投掷)、投掷物(雪球/鸡蛋/喷溅药水)的伤害都加上攻击加成。
5. 例外不计:玩家点燃的 TNT、重生锚爆炸、末地放床爆炸 —— 不加成(判定上天然排除,不要手动写排除逻辑)。
6. PvP 默认不加:远程/投掷物打其他玩家默认保持原版伤害,由配置 pvpDamageBonus(默认 false)控制。
7. 死亡无惩罚:死亡/重登后,已获得的加成永久保留(keepOnDeath 开关)。
8. 生物范围:includePassive / includeHostile / includeBoss / includePlayers 四类开关 + bossMultiplier 倍率 + entityBlacklist 黑名单(默认含 minecraft:armor_stand)。
9. 突破原版上限:原版 max_health 上限 1024、attack_damage 上限 2048 —— 都必须放开。生命上限改为配置 maxHealthCap(默认 1000000 ≈ 无上限);攻击力无上限。联机以主机配置为准。
10. HUD(尽力而为):显示「攻击 +N」「生命 N」两行;血条渲染优先交给 colorfulhearts(可选依赖),没装则用自绘红条,或配置 customHealthBar 关闭。
11. 配置系统:提供可视化配置(本 mod 用 Cloth Config;其它平台用对等方案,如 Forge Config + ModMenu 对等入口)。

【关键机制(实现时务必遵循)】
- 近战加成 = ATTACK_DAMAGE 属性修饰符;远程/投掷物 = 在"实体受伤(hurt)"事件里,判定来源是"玩家拥有的弹射物(Projectile)且 getOwner() 是玩家"才加攻击加成。
- 不要在伤害事件里对"所有玩家伤害"无条件加,否则近战会双倍。
- 加成要在护甲/魔抗减免之前加入(吃护甲,和近战一致)。
- 攻击加成点数必须随玩家存档持久化,近战、远程、HUD 读到同一个数。
- 三个"做不了"的边界(若目标是数据包):突破 1024、远程伤害加成、HUD 渲染 —— 数据包方案做不到这三项,只能做核心玩法一部分(见需求文档/数据包调研)。

【验收标准】
- 徒手/铁剑打怪:伤害 = 原伤害 + 加成;弓/三叉戟/雪球/药水打怪:同样加;TNT/床/锚爆炸:不加。
- 弓箭打玩家:默认原版伤害;开 pvpDamageBonus 后加。
- 击杀后:生命上限、当前血量、攻击加成三者都涨;HUD 与实测一致;死亡重登保留。
- 生命上限可超过 1024;攻击加成超过 2048 后近战仍继续增长。
- 配置项齐全、可改、默认值与上文一致。

【代码风格】
- 用简体中文写详细注释,结构清晰、职责单一;关键设计决策写"为什么"。
- 目标平台如果和原版映射不同,先核实该平台版本的类名/方法名(伤害事件、属性、弹射物、Projectile 归属包等),不要照搬 1.21.11 的 Mojang 名。
```

## 4. 关键机制与已知坑(复刻者必读摘要)

- **伤害加成判定(核心)**:`source.getDirectEntity() instanceof Projectile && getOwner() instanceof Player`,且目标不是玩家(或 `pvpDamageBonus=true`)。TNT/床/锚天然排除。
- **近战 vs 远程**:
  - 近战 = `ATTACK_DAMAGE` 属性修饰符(原版机制,打玩家也生效,这是属性机制决定的)。
  - 远程/投掷物 = 伤害事件里加(本模组用 `@Redirect` 重定向 `hurtServer`→`actuallyHurt`;Forge 用 `LivingHurtEvent.setAmount`;NeoForge 用 `LivingIncomingDamageEvent`)。
  - **不要在事件里给近战重复加,会双倍**。
- **上限突破**:原版 `max_health` 上限 1024、`attack_damage` 上限 2048(均为 `RangedAttribute` 的 maxValue,读取时 `sanitizeValue` 钳制)。必须拦截钳制方法放开上限,否则后期成长被卡死。
- **无敌帧分支**:现代版本 `hurtServer` 内部 `actuallyHurt` 被 if/else 调用两次(互斥)。要么改入口伤害参数(改一次),要么两个调用点都接管(互斥只执行一个)。
- **护甲顺序**:加成在护甲减免之前加入,吃护甲,与近战一致。
- **1.21.11 映射坑(其它平台/版本要对等核实)**:`hurtServer` 多一个 `ServerLevel` 参数;`Projectile` 在 `net.minecraft.world.entity.projectile` 包;`ResourceLocation`→`Identifier`;`RenderTickCounter`→`DeltaTracker`;`MobType` 已移除(用 `MobCategory.MONSTER`)。
- **已知局限(设计如此,不必"修复")**:
  - 生命上限配置对所有实体的 max_health 都生效(属性不知道归属;默认 1000000 无影响)。
  - 近战打玩家仍带属性加成(pvpDamageBonus 只控制远程/投掷物)。
  - 黑名单/新配置默认值只对"全新配置文件"生效;已有存档需手动改配置。

## 7. 给用户的提醒

- **不要直接把原版 Fabric 源码当"最终答案"发给另一个 AI 抄**—— 让 AI 按规格(§1 提示词 + §2 文档)在自己的目标平台重新实现,遇到平台差异要它**先核实该平台的 API**(伤害事件、属性命令/系统、类名),再写代码。
- 原版实现里有两个"平台特定的妥协"是历史踩坑结果,复刻到别的平台时**不必照搬踩坑**,直接按规格里的"推荐做法"走:
  - `@ModifyVariable` 在 Fabric mixin 0.8.x 会静默失败 → 用 `@Redirect`(或事件)。
  - Cloth Config 必须先 register 再 getConfigHolder → 换对等配置库时按该库规范来。
